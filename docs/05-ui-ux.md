# 05. UI / UX 設計（スマホ縦持ち）

## 5.1 前提

- 基準端末：**iPhone 幅 390px × 高さ 844px**（CSS px）。
- 高さは `100dvh` を使う（iOS Safari のアドレスバー伸縮対策）。`100vh` は使わない。
- `env(safe-area-inset-bottom)` を下部パディングに必ず加算する。
- **親指到達範囲は画面下 1/3**。主要操作（スピン／3択の決定）はここに置く。
- 上部は情報表示のみ。タップ対象を置かない。

**家賃ゲージは画面下部、スピンボタンの直上に置く。** 当初はヘッダに

増えていく演出にしてほしい」という要望を受けて、コインの着地点
（gain-area）に近い下部へ移動した（詳細は5.4.2）。

## 5.3 3択（ボトムシート）

スピン解決後、下から**ボトムシート**がせり上がる。盤面は上半分に残す
（**「今の盤面を見ながら選ぶ」ことがこのゲームの意思決定そのもの**なので、盤面を隠さない）。

```
│   （盤面は上に残る・やや暗く）    │
├──────────────────────────────┤
│  どれを入居させる？             │
│ ┌────────┬────────┬────────┐ │
│ │   🐔   │   🍺   │   🏆   │ │
│ │ ニワトリ│ 缶ビール│優勝カップ│ │
│ │ 3スピン │ 隣の住人│ 隣接の値 │ │
│ │ ごとに🥚│ に +3  │ を ×2   │ │
│ │ ★★☆☆ │ ★★☆☆ │ ★★★☆ │ │
│ └────────┴────────┴────────┘ │
│                              │
│      見送る（+5コイン）        │
└──────────────────────────────┘
```

- カードは**タップで選択確定ではなく、1タップで拡大表示 → もう1タップで確定**。
  誤タップでビルドが壊れる事故を防ぐ（このジャンルでは1枚の誤選択が致命傷になる）。
- 拡大表示中は、**そのシンボルと噛み合う所持シンボルを盤面上でハイライト**する
  （虫めがねアイテム所持時は常時）。初心者がシナジーを発見する主導線。
- **表示は、コインの演出が全て完全に終わってから。** スピン演出（①②③④⑤、
  5.4参照）の最後の1枚が財布へ吸い込まれ終わるまで、ボトムシート（3択も
  ショップも）は絶対に出さない。演出の途中で結果画面が出てしまうと、
  「まだコインが飛んでいるのに次の操作を迫られる」ちぐはぐな体験になるため。
- **演出の途中で画面のどこかをタップすると、残り全部を即座にスキップして
  結果を確定し、そのまま3択（またはショップ）へ進む。** スキップ操作は
  いつ・どの段階で押しても同じ着地点（＝次の画面）に必ずたどり着く。

## 5.4 スピン演出

**「どのマスがいくら稼いだか」を1マスずつ順に見せる**のがこの演出の主目的。
まとめて出すと数字が一度に増えるだけで、シナジーを組んだ実感が残らない。

順番は**盤面インデックスの昇順＝左上から右下への読み順**。
これはエンジンの効果解決順（02.3）と一致しており、説明が一本化される。

**金額は数字では出さない。** マスの上に数字バッジを置く案（`+N`の
テキストポップアップ含む）は試したが撤回した。**現在の方針は
「コインが飛んで、そのターンの合計金額へ吸い込まれる」動きと枚数だけで
増加を伝える**（5.4.2）。数字が残るのは gain-area の合計金額と、
上部のコイン残高だけ。

**2段構えにする。**

| 段 | 内容 | 1つあたり |
| --- | --- | --- |
| 落下 | 各列が上から下へスライドイン（列ごとに 34ms ずらし）。列ごとに停止音 | 計 0.26s |
| **① 基礎金額** | 盤面のシンボルの**素の値**ぶんのコインを、読み順に 1マスずつ飛ばす | **0.1秒／マス（下記参照）** |
| **② 特殊効果** | **コンボ**（＝1つのシンボルが1つの相手に対して起こす一連の作用）が1つずつ発動する。<br>**発動したシンボルと、その相手を同時に光らせ**、増えたぶんのコインを飛ばす | **0.1秒／コンボ（下記参照）** |
| 倍率 | 合計に倍率が乗る場合、`+53 × 3` を見せてから最終値へ | 0.34s |
| 精算 | コイン表示がカウントアップ | 0.22s |

**①と②を分ける理由**：まず「素の値がいくらか」を全部見せてから、
「そこに何がどう乗ったか」を1つずつ見せる。混ぜると、増加が
基礎なのか効果なのか区別できず、シナジーを組んだ実感が残らない。

### コンボの区切り方

**1コンボ = 1つのシンボルが、1つの相手に対して起こす一連の作用。**
「相手」が変わるたびに新しいコンボとして区切る。

- おばあちゃんが隣の住人3人を強化する → **3コンボ**（相手が3回変わる）
- ノラ猫がネズミを2匹食べる → **2コンボ**（1匹ごとに、破壊・死亡時効果・報酬の
  3操作が発生するが、同じ相手＝同じコンボとして束ねる）

後者を分割してしまうと「1匹食べる」という1つの出来事が3つのアニメーションに
バラけてしまうため、**エンジン側**（`src/core/engine.js`）が各操作に
「相手が誰か」を表す `comboKey` を付け、UI はそれが変わった時だけ区切る。
UI 側は`result.steps`をそのまま再生するだけで、演出のためにルールを再実装しない。

- **破壊は、それを起こしたコンボを再生した瞬間**に見せる。
  落下時点でグレーにすると、壊した側が動く前に結末が見えてしまう。
- **盤面のマスに紐付かない加算（アイテムの定額ボーナス等）も、無音で飛ばさない。**
  ①②の表示だけでは最終合計に届かない差分が残っていたら、②の後にもう1段、
  他のコンボと同じ0.1秒のアニメーションとして加算する。これが無いと、
  ボロ財布のようなアイテムを持っている時だけ最後に無言でジャンプし、
  「合計金額になるまで一つずつ」という流れが壊れる。
- **画面のどこかをタップすると演出を即スキップ**（残りは一括表示）。
  スキップ時はコインを飛ばさない（追いつかないため）。破壊マスのグレー
  アウトだけ即座に反映し、合計は最終値へ直接ジャンプする
- **高速モード**：ボタンでON。演出を全部飛ばして即結果。長時間プレイ向け。
- 枠の強調（`pulseCell` / `.cell.acting` / `.cell.involved`）は**いま動いている
  1マスだけ**に付ける。加算済み全部に付けると、終盤には盤面のほぼ全マスが
  光って何の情報にもならない。数字を出さない代わりに、この一瞬の強調と
  飛んでいくコインが「ここが動いた」を伝える

### コイン飛翔演出（増分の見せ方）

**マスの上に常時居座る金額バッジは置かない。** 主役は**コインが飛び散って、
そのターンの合計金額（gain-areaの `+XX`）へ吸い込まれる動きと枚数**で、
「何が起きているか」の実感はそこで作る。ただし「このマスがこの一手で
実際にいくら稼いだか」は、コインの枚数（sqrt圧縮・最大7枚の見た目の量）
だけでは読み取れないため、**実額を一瞬だけ数字で見せるスコア表示**を
別途添える（当初は数字を一切出さない方針だったが、「シンプルにスコア
表示してほしい」という要望を受けて実額表示に戻した）。

コンボが発動するたびに対象マスで起こるのは、①②の**間は**次の2段階だけ。

1. **実額を一瞬表示**：`+N`（この一手の実際の増分）を**スコア風フォント**
   （背景の無い太い縁取り数字のシンプルな表示）でマス上にポップさせる
   （`showScoreBadge()`）
2. **散らばって、その場に留まる**：金額と同じ枚数のコインが、上限なしで
   それぞれ思い思いの方向へ弾け出て、散らばった位置で**静止して待つ**
   （`spawnCoin()`・`scatteredCoins` に積まれる）。**①②の演出が続いている間は
   一切合計へ飛ばない** ── コインは画面上にどんどん散らばって溜まっていく
   - 枚数は「平方根で圧縮」→「上限7枚」→「上限20枚」→「上限なし」と
     変遷した。①のバッジで実額の `+N` を同時に出すようにしたため、
     圧縮していると「+10なのにコインが4枚しか出ない」ように見えて
     食い違いが目立ってしまい、枚数=金額そのままにした。当初は
     「線形のまま青天井にすると重くなる・画面が埋まる」という懸念から
     20枚で頭打ちにしていたが、「出てくるコイン枚数の上限はいらない、
     何枚でも出る演出続いて良い」という要望を受けて上限を撤廃した
     （実測で200枚超のバーストでも残留・エラーなく動作することを確認済み）
   - **散らばる半径も枚数に比例させる**（`spawnCoin()` の `scale = min(1, count / 10)`
     を半径・浮き上がり量の両方に掛ける）。1枚だけ出た効果まで、10枚以上
     出た効果と同じ広さで弾けると、小さい効果ほど大げさに見えてしまうため。
     1枚の時はマスの上でごく軽く揺れる程度、10枚以上でこれまでどおりの
     広い散らばりになる
   - **既に画面に散らばって静止している他のコインとも、なるべく被らない
     位置を選ぶ**（`pickScatterPositions()` / `pickOneScatterPosition()`）。
     角度と半径を完全ランダムに1回だけ決めていた当初は、真上に重なって
     「1枚しか出ていないように見える」ことがあったため、候補を6個出して
     一番マシ（既存のコイン・同じバースト内の他のコインの両方から最も
     遠い）ものを選ぶ、簡易なブルーノイズ的間引きに変更した。衝突判定で
     押し出す等の厳密な重なり回避まではしない ── 見た目の自由な散らばり
     方は保ちつつ、一番目立つ「真上ぴったり重なり」だけを避ける狙い。
   - **枚数の上限を撤廃した結果、通常の半径の中だけでは空きが無くなる
     ケースが増えたため、半径の外へはみ出してでも空いている場所を優先する
     ようにした。** SCATTER_RADIUS_RINGS（`[1, 1.8, 3, 5, 8]`）の倍率を
     内側から順に試し、SCATTER_MIN_GAP（16px、コイン本体の直径とだいたい
     揃えた値）以上離れた候補が見つかった時点でそのリングで確定する。
     空いていれば従来どおり内側の輪だけで決まるので、通常の枚数（数枚〜
     十数枚程度）では見た目は変わらない。混んできた時だけ外側までじわじわ
     広がっていく（「半径からはみ出てもいいので、既存のコインと
     被りすぎないように配置することを優先してほしい」という要望）。
     それでも画面上のコインが極端な枚数（数百枚）まで積み上がれば、
     重なりが完全にゼロにはならない（空いている場所自体が有限のため）

3. **全部の演出が終わってから、まとめて一斉に吸い込む**：①②のすべてが終わり
   「財布に入る」段になったところで初めて、それまで画面に散らばっていた
   **全コイン**が gain-area の合計表示へ一斉に吸い込まれる（`absorbAllCoins()`）。
   1枚ずつ・コンボごとにバラバラ回収するより、「最後に画面じゅうのコインが
   一気に集まる」ほうが締めの一撃として気持ちいいため

- **1枚ずつ、ABSORB_STAGGER_MS（32ms）の等間隔で吸い込み始める。**
  「1枚ずつ聞き分けられるジャラッ、ジャラッ、ジャラッ」というリズムが
  目的（16msだと複数枚がほぼ同時着地して音が塊に潰れる。65msでは
  遅いという声を受けてその半分の32msに調整した）
- タイミングは基本すべて固定値（`COIN_STAGGER_MS` / `COIN_SCATTER_MS` /
  `COIN_SUCK_MS` / `ABSORB_STAGGER_MS`）で、ランダムにしているのは散らばる
  方向・広がり幅という見た目の変化だけ。**「音のタイミングに規則性がない」
  という指摘を受けて、飛行時間のランダムな幅は撤回した**
- 加算（濃いめの金）と乗算（明るい金）でコインの色味を変える
- **見た目は盤面のコインシンボル（sprites.js の coin）と同じ絵作りに揃えた**：
  くっきりしたインクの輪郭線（`var(--sp-ink)`）＋内側の一段暗いリング＋
  左上のハイライト。ぼかしたグロー（box-shadow blur）だけで縁取っていた
  当初案は、演出後半で何十枚も画面に重なった瞬間に金色同士が溶けて
  「塊」にしか見えなくなる問題があったため撤回した。輪郭・段差・落ち影は
  すべて「にじまない」表現に統一し、重なっても1枚ずつの縁が識別できる
  ことを優先する
- 破壊（destroy）には付けない。壊れたことはグレーアウトが伝える
- **描画は単一の `<canvas>`（`#coin-layer`）へのまとめ描きで、コイン1枚
  ごとにDOM要素は作らない。** 当初はコイン1枚＝1個の `<div class="coin-fly">`
  で、1枚ごとに自前の `requestAnimationFrame` 連鎖を持たせていたが、
  コインの枚数上限を撤廃した結果1バーストで数百枚生成されることも
  あるようになり、数百個のDOM要素（box-shadow・グラデーション付き）と
  数百本の並行rAFが古いスマホで重くなっていた。「言語構成を、古い
  スマホでも軽い処理で動かせるものに変えたい（コイン演出が重い）」
  という要望を受けて、DOM粒子方式から canvas 一括描画方式に作り直した
  （`src/ui/app.js` の `particles` 配列＋`coinLoop()`）。
  - コインの見た目は起動時に一度だけオフスクリーンcanvasへ焼き込み
    （`buildCoinSprites()` / `renderCoinSprite()`）、毎フレームはその
    焼き込み済みビットマップを `drawImage` で貼るだけにした。パスや
    塗りの再計算をフレームごとに行わない。
    **最終的には、盤面のコインシンボル（sprites.js の `coin`）と全く同じ
    4層構成で焼いている**：①単色フラットな円塗り（グラデーションでは
    ない）②内側の一段暗いリング（ストロークのみ）③左上の三日月形
    ハイライト（塗りつぶした円ではなく弧のストローク）④外側のインク
    輪郭線。色も `PALETTE.gold` / `goldDk` / `goldLt`（＝`--accent` /
    `--accent-2` と同値）をそのまま使っている。canvas化した直後は、
    DOM版CSS（`.coin-fly` の `radial-gradient`）を模した「ぼかした
    グラデーション塗り」を焼いてしまい、盤面シンボルとは違う印象に
    なっていた。「シンボルのコインに近い見た目だったはず」という指摘の
    とおり、これはこのセッションの早い段階で決めた方針（同じ絵作りに
    揃える）からの後退だったため、盤面シンボルの技法へ焼き直した。
    重なった時の識別性のための右下への軽い落ち影だけは、盤面シンボルには
    無い演出専用の味付けとして残している（DOM版CSSの `box-shadow` の
    ドロップシャドウ成分の名残）
  - 全コインの状態は軽量なプレーンオブジェクトの配列で持ち、コインが
    何枚いても共有の rAF ループ1本（`coinLoop()`）で全員ぶんまとめて
    「時間から位置を計算 → 描く」を行う。コインが1枚もいない間はループ
    自体を止める
  - 座標系・タイミング（COIN_SCATTER_MS・ABSORB_STAGGER_MS等）や散らばり
    位置の選び方（`pickScatterPositions()`）はDOM版から変えていない ──
    見た目・挙動は保ったまま、描画の実装だけを軽量化した
  - **吸い込み（合計への飛翔）のイージングを、3乗（`easeInCubic`）から
    2乗（`easeInQuad`）に緩めた。** 3乗だと k=1 付近で速度が急激に伸び、
    60fps（1フレーム約16.7ms）環境でも最終フレームだけ数十px動いて
    しまい、「吸い込まれる時のアニメーションが少し飛んで見える」という
    指摘につながった。実測では、フレームごとの最大移動距離が約60.8px→
    約41.8pxまで下がることを確認した。「吸い込まれて加速する」感触は
    保ちつつ、末尾の速度スパイクだけ抑える狙い
  - 実測（Chromium・headless）では、育てた植木鉢で300枚超のコインが
    出るバーストでもフレーム間隔が安定して約16.7ms（60fps）に収まり、
    フレーム落ちが発生しないことを確認した

**①②とも、コインが出きるまで待つように変更した。**
`burstCoins()` は生成した最後の1枚をトリガーした時点で解決する Promise を
返すようになっており、①（1マスごと）も②（`playBeat()` 1コンボごと）も
「固定の間隔（① BASE_STEP_MS＝0.1秒 / ② EFFECT_STEP_MS＝0.1秒。
①②で揃えてある）」と「そのバーストが全部出きるまでの時間」の
**長い方**を `Promise.all` で待つ。小さい効果（固定間隔＝生成間隔ぶんの
枚数以内で収まる量）はこれまでどおりのテンポで進むが、大きい効果
（例：育った植木鉢や、パチンコ玉の+60→60枚、19×30ms≒570ms）は
次へ進むまでの間隔がその分伸びる（枚数に上限が無いため、非常に大きい
効果は非常に長い間隔になる ── これ自体は仕様どおり）。「①も1マス＝
1コンボという認識なので、
②と同じ仕様に。ジャララと出て0.1秒、次がまたジャララと出て…を繰り返す
イメージ」という要望を受けた変更で、実測でも育てた植木鉢の①バースト後は
次のマスまで約570ms、②の+60コンボの後は次のコンボまで約570msと、通常の
マス／コンボの約100msに対してはっきり長くなることを確認した。
（②のEFFECT_STEP_MSは当初0.2秒だったが、「②のコンボ時の演出の隙間も
0.1sになってますか？なってなければして」という要望を受けて①と揃えて
0.1秒にした。）

**実装上の注意（レースコンディション、なお残る部分）**：`burstCoins()`
の Promise は「最後の1枚をトリガーした瞬間」に解決するのであって、
「最後の1枚が散らばり終える（COIN_SCATTER_MS＝130ms後）」までは待たない。
そのため、次のマス／次のコンボが始まった直後の最大130msだけ、前の
バーストの最後の数枚がまだ散らばり中ということがあり得る。さらに、①②の
演出全体が終わって`absorbAllCoins()`が呼ばれた**その瞬間にまだ散らばり
終えていないコイン**も同様にあり得る。これらを「もう吸収は始まっている
か」というフラグ（`absorbing`、`nextSlotAt` で次の出発時刻を共有）で
判定し、遅れて散らばり終えたコインも**同じ32ms間隔のスケジュールに
乗せて**出発させる。独自のタイミングで即座に合流させてしまうと、その
部分だけ間隔が乱れてリズムが崩れるため。そうしないと数枚だけ回収されず
に迷子になり、次のスピンまでコイン要素が残留し続ける不具合にもなる
（実測で発見・修正済み）。
- **音も視覚に同期させる。** コインが弾け出た瞬間に短い打音の「ジャッ」
  （`sfx.coinPop`）、合計へ着地した瞬間に短い打音の「チッ」
  （`sfx.coinLand`）が鳴る。どちらも ABSORB_STAGGER_MS（32ms）/
  COIN_STAGGER_MS（30ms）という短い等間隔で連続して鳴るため、積み重なって
  それぞれ「ジャラララ…」「チッチッチッ…」という連打の粒立ちになる。
  coinPop は当初、純音だけの柔らかい「ポッ」だったが、「1枚ずつ高速で
  ジャラララと出てくる感じにしたい」という要望を受けて、ノイズの粒を
  混ぜた coinLand 寄りの質感に変更し、生成間隔も45ms→24ms→（「もう少し
  だけ広げて」との要望で）30msに調整した（出てくる時「ジャラララ」・
  入る時「チッチッチッ」で、音色は変えつつ高速な連打感は揃えている）。
  **音程は着地順で変えない** ── coinLand は
  当初、着地順に音程を一段ずつ上げていく設計だったが、「音程が変わる
  高い音はいらない、チッチッと重なるような音だけでいい」という指摘を
  受けて撤回した。
  毎回ほぼ同じ高さの打撃音にすることで、粒が重なった時の「チッチッチッ」
  という連打感そのものを聞かせる音作りに変えている（ごく小さいランダムな
  ゆらぎだけは残し、無機質になりすぎないようにしている）。
  ①②のトリガー音（`sfx.coin` / `sfx.combo`）は「発動の合図」役に徹し、
  控えめにした ── 主役はコインの音になったため
- CSSアニメーションではなく canvas への毎フレーム描画で座標を直接
  計算しているため、`prefers-reduced-motion` はCSSだけでは効かない。
  JS側でも `matchMedia` を見て、該当時はコインを生成しない（情報は
  欠落しない ── gain-area の合計金額は変わらず更新されるため）
- 描画先は `#coin-layer`（`#app` 直下の専用 `<canvas>`）。盤面をまたいで
  gain-area まで飛ぶため、セルの中には置けない。devicePixelRatio に
  合わせて実ピクセル数を上げているが、上限は2に頭打ちしている（非常に
  高DPRな端末でcanvasが必要以上に大きくなって重くなるのを避けるため）
- **`<canvas>` は `<div>` と違い、置換要素なので `position:absolute;
  inset:0` だけでは親いっぱいに広がらない。** 明示的に `width:100%;
  height:100%` を指定しないと、既定の内在サイズ（300×150px）のまま
  レイアウトされてしまい、コインがその小さな矩形の中にしか描画されず
  「コインが画面に出ていない」ように見える不具合になる（canvas化した
  直後に実際に発生・修正した）。canvas を使った描画レイヤーを追加する
  時は毎回このCSSを忘れないこと

> マス単位の内訳（このコンボで実際にいくら稼いだか）は、演出中に一瞬
> `+N` のスコアバッジとして表示されるだけで、演出後には残らない。
> 見逃した場合、盤面のシンボルを長押しすれば効果テキストは見られるが、
> 過去の金額そのものは見えない。もし「あとで内訳を確認したい」ニーズが
> 出てきたら、リザルト画面などに別途集計を出す形で対応する
> （今回はスコープ外）。

### 5.4.2 家賃ゲージ・所持コイン表示・獲得表示との連動

**家賃ゲージ（画面下部の `.rent-bar`）も、ヘッダーの所持コイン表示
（`#coins`、💰の隣の数字）も、画面下の獲得表示（gain-area の `+N`）も、
コインが財布へ着地するたびに少しずつ増える。** ①②の演出中は溜まって
いくだけで動かず、⑤「財布に入る」段になって初めて動き出す ── コインの
動き自体（5.4.2冒頭のコイン飛翔演出）と同じ考え方で、「まとめて増える」
より「1枚ずつ増えていく」方が締めの一撃として気持ちいいため。

- `absorbAllCoins()` はスピン開始時点の値（所持コインは `coinsBefore`、
  獲得表示は倍率反映前の `running`）→このスピン確定後の値（所持コインは
  `run.coins`、獲得表示は倍率反映後の `result.total`）を、「今まで何枚の
  うち何枚が着地したか」の比率で線形補間して、`rent-fill` の `width`・
  `#coins`・gain-area の `+N` の3つに同時に反映する。1枚着地するたびに、
  3つとも1段ずつ同時に更新される。
  以前は `#coins` 側だけ `countUp()` という別の固定尺（220ms）タイマーで
  独自に動き、gain-area 側は absorbAllCoins() を呼んだ瞬間に
  `result.total` へ即座に書き換えていた。これだと大きい効果で吸収が
  何秒もかかる時に「所持コイン・獲得表示の数字だけ先に確定してしまい、
  まだコインが画面を飛んでいる」というちぐはぐな見え方になっていた。
  「合計コインカウント数は最初から表示せず、コインが吸い込まれる
  タイミングに合わせて数字が増える仕様にしてください」「画面下にある
  +◯の所も同じ仕様にして欲しい」という指摘を受けて、`countUp()` を廃止し
  gain-areaの即時書き換えもやめて、3つとも同じ着地イベント駆動にした。
  これにより、`#coins` は最初の1枚が着地するまで `coinsBefore` のまま、
  gain-area は `running`（倍率が乗る演出で見せていた「+53 × 3」の
  「53」部分）のまま動かず、最終的な数字は演出の開始時点ではまだ表示
  しない。倍率演出（④）の「× 3」表記は、吸収が始まった瞬間に外れて
  素の数字表示へ切り替わり、そこから着地に合わせて実際の最終値まで
  増えていく
- **なめらかな連続増加ではなく、「メモリが増える」ような刻んだ動きに
  している。** 最初は CSS の `transition: width .35s ease-out` に
  任せていたが、トランジション時間（350ms）が着地間隔（ABSORB_STAGGER_MS
  ＝32ms）よりずっと長かったため、複数回の離散更新が滑らかに繋がって
  見え、連続的なアニメーションに見えてしまっていた。「ゲージの動きは
  連続的じゃなくて、コインの吸い込まれるタイミングに合わせてメモリが
  増えるような挙動にできませんか」という指摘を受けて、トランジションを
  着地間隔より短い 24ms（styles.css・`RENT_FILL_TRANSITION_MS` の
  両方で揃える）に短縮した。0（完全な瞬間移動）にはせず、ごく短いだけの
  動きを残すことで、味気なくなりすぎない程度のスナップ感を持たせている。
- **`absorbAllCoins()` は全部着地し終わるまで待てる Promise を返す**
  ── `animateSpin()` はこれを待ってから戻るので、次の画面（3択・
  ショップ）は必ずゲージが伸びきった後に表示される（5.3参照）。
  「最後の1枚が着地した瞬間」だけでは不十分な点に注意：`rent-fill`の
  最終的な `width` を設定してから、実際に画面上でそこまで伸びきる
  （＝上記のトランジションが終わる）までにはまだ猶予がある。そこで、
  最後の着地後に `RENT_FILL_TRANSITION_MS` ぶんだけ追加で待ってから
  resolve する。これを入れないと、ゲージがまだ視覚的に伸びている
  途中で3択が出てしまう（実際に指摘を受けて追加した）。この追加待機中の
  タップも `wait()` 経由なので、通常どおりスキップできる。
- 演出中にタップしてスキップした場合は、残っているコインを全部即座に
  片付け、ゲージ・`#coins`・gain-areaの3つとも確定後の値へ即座にジャンプ
  する。「1枚ずつ増える演出」を見るか、スキップして結果だけ見るか、
  常にどちらでも最終的な値は同じになる。

### 注意：一斉発動系の効果は膨大なコンボ数になる

大家さん（盤面の全シンボルに +2）や満月（盤面の全動物に +4）のような
「一斉に効果を出す」タイプは、対象の数だけコンボが生成される。
最大構成（大家さん1体・他19マス埋まっている）だと **19コンボ×0.1秒＝1.9秒**が
その1シンボルだけで発生する。0.5秒だった時期に比べれば軽くなったが、
実機で気になるようなら、一斉発動系だけ例外的に
「対象をまとめて同時に光らせる1コンボ」として扱う、といった調整が必要になる。

### 尺の見積もり（要注意）

盤面20マス・効果が5コンボなら **0.26 + 2.0 + 0.5 + 0.2 ≒ 3.0秒／スピン**。
効果が10コンボあると **3.5秒**前後になる。1ラン114スピンだと
**6分前後がアニメーションの時間**になる（②のテンポを0.2秒→0.1秒に
した分、以前の見積もりより短くなった）。

当初の「1スピン1.2秒上限」からは伸びている。
テンポの最終判断は実機での体感待ち（6.3の検証項目）。
調整は `src/ui/app.js` の `BASE_STEP_MS` / `EFFECT_STEP_MS` の2定数だけで効く。

## 5.4.1 効果音

音声ファイルは持たず、**Web Audio でその場で合成**する（`src/ui/audio.js`）。
アセット0・オフライン可・初回ロード増加なしを保ちつつ、
「加算のたびに音程を上げる」といった動的な鳴らし方が素直に書ける。

| 音 | 用途 |
| --- | --- |
| レバー / 列停止 | スピン開始と各列の着地 |
| コイン音（①） | 基礎金額が1マスずつ並ぶとき |
| **コンボ音（②）** | 特殊効果が1コンボずつ発動するとき。①とは意図的に違う音色にし、<br>耳でも①②を区別できるようにする。短いクリック（アタック）＋和音で<br>「ヒットした」感を出す |
| 破壊音 | シンボルが壊れたとき（ノイズバースト） |
| 倍率音 | 合計に倍率が乗ったとき |
| 支払い成功 / 失敗 / 完済 | 期の区切り |
| タップ / 購入 / 廃棄 | UI操作 |

①②とも、**表現は音程の軸だけに絞る**。①はマスの並び順、②はスピン内で
通したコンボの順番で、進むほど音階（ペンタトニック）を上がっていく
── 「積み上がっている」感。

> 金額の大小で音量・音色を変える案（段階制→連続値）も試したが、
> 「コンボの音程だけで表現する」方針に一本化した。大きい金額かどうかは
> 盤面のポップアップ `+N` / `×N`（見た目）が伝えるので、音と役割を分けている。

- **ミュートトグルを常時表示**（下部ボタン）。設定は localStorage に保存し、リロードをまたぐ。
- ブラウザの自動再生制限があるため、**AudioContext は最初のタップまで生成しない**。
- 音は完全に任意。**無音で情報が欠落してはいけない**（5.8）。

## 5.5 情報設計の原則

1. **数字は常に見える。** コイン・家賃・残スピンは常時表示。モーダルで隠さない。
2. **「あと何コイン足りないか」を出す。** 家賃バーは残額を赤字で表示（`あと 58`）。
   これがラン中の緊張の源泉。
3. **効果テキストは盤面のマスを長押しで表示。** タップは選択、長押しは説明、で統一。
4. **色に意味を持たせない。** 色覚特性への配慮として、レアリティは★の数と枠線の形で示す。
