# 05. UI / UX 設計（スマホ縦持ち）

## 5.1 前提

- 基準端末：**iPhone 幅 390px × 高さ 844px**（CSS px）。
- 高さは `100dvh` を使う（iOS Safari のアドレスバー伸縮対策）。`100vh` は使わない。
- `env(safe-area-inset-bottom)` を下部パディングに必ず加算する。
- **親指到達範囲は画面下 1/3**。主要操作（スピン／3択の決定）はここに置く。
- 上部は情報表示のみ。タップ対象を置かない。

## 5.3 3択（ボトムシート）

スピン解決後、下から**ボトムシート**がせり上がる。盤面は上半分に残す
（**「今の盤面を見ながら選ぶ」ことがこのゲームの意思決定そのもの**なので、盤面を隠さない）。

```
│   （盤面は上に残る・やや暗く）    │
├──────────────────────────────┤
│  どれを入居させる？             │
│ ┌────────┬────────┬────────┐ │
│ │   🐔   │   🍺   │   🏆   │ │
│ │ ニワトリ│ 缶ビール│優勝カップ│ │
│ │ 3スピン │ 隣の住人│ 隣接の値 │ │
│ │ ごとに🥚│ に +3  │ を ×2   │ │
│ │ ★★☆☆ │ ★★☆☆ │ ★★★☆ │ │
│ └────────┴────────┴────────┘ │
│                              │
│      見送る（+5コイン）        │
└──────────────────────────────┘
```

- カードは**タップで選択確定ではなく、1タップで拡大表示 → もう1タップで確定**。
  誤タップでビルドが壊れる事故を防ぐ（このジャンルでは1枚の誤選択が致命傷になる）。
- 拡大表示中は、**そのシンボルと噛み合う所持シンボルを盤面上でハイライト**する
  （虫めがねアイテム所持時は常時）。初心者がシナジーを発見する主導線。

## 5.4 スピン演出

**「どのマスがいくら入れたか」を1マスずつ順に見せる**のがこの演出の主目的。
まとめて出すと数字が一度に増えるだけで、シナジーを組んだ実感が残らない。

順番は**盤面インデックスの昇順＝左上から右下への読み順**。
これはエンジンの効果解決順（02.3）と一致しており、説明が一本化される。

**2段構えにする。**

| 段 | 内容 | 1つあたり |
| --- | --- | --- |
| 落下 | 各列が上から下へスライドイン（列ごとに 34ms ずらし）。列ごとに停止音 | 計 0.26s |
| **① 基礎金額** | 盤面のシンボルの**素の値**を、読み順に 1マスずつ並べる | **0.1秒（固定）** |
| **② 特殊効果** | **コンボ**（＝1つのシンボルが1つの相手に対して起こす一連の作用）が1つずつ発動する。<br>**発動したシンボルと、その相手を同時に光らせ**、増えた分だけ**差分ポップアップ**（+N / ×N）が浮かぶ | **0.2秒／コンボ** |
| 倍率 | 合計に倍率が乗る場合、`+53 × 3` を見せてから最終値へ | 0.34s |
| 精算 | コイン表示がカウントアップ | 0.22s |

**①と②を分ける理由**：まず「素の値がいくらか」を全部見せてから、
「そこに何がどう乗ったか」を1つずつ見せる。混ぜると、増えた数字が
基礎なのか効果なのか区別できず、シナジーを組んだ実感が残らない。

### コンボの区切り方

**1コンボ = 1つのシンボルが、1つの相手に対して起こす一連の作用。**
「相手」が変わるたびに新しいコンボとして区切る。

- おばあちゃんが隣の住人3人を強化する → **3コンボ**（相手が3回変わる）
- ノラ猫がネズミを2匹食べる → **2コンボ**（1匹ごとに、破壊・死亡時効果・報酬の
  3操作が発生するが、同じ相手＝同じコンボとして束ねる）

後者を分割してしまうと「1匹食べる」という1つの出来事が3つのアニメーションに
バラけてしまうため、**エンジン側**（`src/core/engine.js`）が各操作に
「相手が誰か」を表す `comboKey` を付け、UI はそれが変わった時だけ区切る。
UI 側は`result.steps`をそのまま再生するだけで、演出のためにルールを再実装しない。

- **破壊は、それを起こしたコンボを再生した瞬間**に見せる。
  落下時点でグレーにすると、壊した側が動く前に結末が見えてしまう。
- **盤面のマスに紐付かない加算（アイテムの定額ボーナス等）も、無音で飛ばさない。**
  ①②の表示だけでは最終合計に届かない差分が残っていたら、②の後にもう1段、
  他のコンボと同じ0.2秒のアニメーションとして加算する。これが無いと、
  ボロ財布のようなアイテムを持っている時だけ最後に無言でジャンプし、
  「合計金額になるまで一つずつ」という流れが壊れる。
- **画面のどこかをタップすると演出を即スキップ**（残りは一括表示）。
- **高速モード**：ボタンでON。演出を全部飛ばして即結果。長時間プレイ向け。
- 枠の強調は**いま動いている1マスだけ**に付ける。加算済み全部に付けると、
  終盤には盤面のほぼ全マスが光って何の情報にもならない。金額は残る数字が伝える。

### 差分ポップアップ（+N / ×N）

マス上の合計バッジは「今いくらか」という絶対値の表示。0.1秒ペースで
数字が切り替わり続けると、変化量そのものは読み取りにくい。
「いくら増えたか」を伝える役目は**差分ポップアップが専任する**：
コンボが発動した瞬間、対象マスの中央から緑（加算）か金（乗算）の
`+N` / `×N` がふわっと浮き上がって消える。

- 合計バッジより目立つ色・大きさにする（バッジは絶対値、ポップアップが主役）
- 使い捨てのDOM要素として都度生成し、アニメーション終了で自分から消える。
  寿命（0.6秒）がコンボ間隔（0.1秒）より長いので、連続するコンボの分が
  画面上に何個も重なって浮かぶ ── それによって「勢いよく積み上がっている」
  ことが一目でわかる（15スピン後に残留要素が無いことを確認済み）
- 破壊（destroy）には付けない。壊れたことはグレーアウトが伝える

### 注意：一斉発動系の効果は膨大なコンボ数になる

大家さん（盤面の全シンボルに +2）や満月（盤面の全動物に +4）のような
「一斉に効果を出す」タイプは、対象の数だけコンボが生成される。
最大構成（大家さん1体・他19マス埋まっている）だと **19コンボ×0.2秒＝3.8秒**が
その1シンボルだけで発生する。0.5秒だった時期に比べれば軽くなったが、
実機で気になるようなら、一斉発動系だけ例外的に
「対象をまとめて同時に光らせる1コンボ」として扱う、といった調整が必要になる。

### 獲得値ラベルの置き方

**タイルの上端をまたぐ位置に、枠付きの金色のラベルとして出す。**
マスの隅に小さな数字を置くと「今いくらか」が読み取れない。ラベルは盤面や
隣のマスにはみ出してよい（むしろ重なるほど派手で、スロットとしては正しい）。

- 位置: マス上端中央（`translate(-50%, -50%)`）。最上段は盤面の外にはみ出す
- 動き: 下から跳ね上がって少しオーバーシュートしてから落ち着く（0.22秒）
- 重なり: **いま加算中のラベルを最前面**に。それ以外は盤面の並び順どおり

### 尺の見積もり（要注意）

盤面20マス・効果が5コンボなら **0.26 + 2.0 + 1.0 + 0.2 ≒ 3.5秒／スピン**。
効果が10コンボあると **4.5秒**前後になる。1ラン114スピンだと
**7〜8分前後がアニメーションの時間**になる。

当初の「1スピン1.2秒上限」からは伸びている。
テンポの最終判断は実機での体感待ち（6.3の検証項目）。
調整は `src/ui/app.js` の `BASE_STEP_MS` / `EFFECT_STEP_MS` の2定数だけで効く。

## 5.4.1 効果音

音声ファイルは持たず、**Web Audio でその場で合成**する（`src/ui/audio.js`）。
アセット0・オフライン可・初回ロード増加なしを保ちつつ、
「加算のたびに音程を上げる」といった動的な鳴らし方が素直に書ける。

| 音 | 用途 |
| --- | --- |
| レバー / 列停止 | スピン開始と各列の着地 |
| コイン音（①） | 基礎金額が1マスずつ並ぶとき |
| **コンボ音（②）** | 特殊効果が1コンボずつ発動するとき。①とは意図的に違う音色にし、<br>耳でも①②を区別できるようにする。短いクリック（アタック）＋和音で<br>「ヒットした」感を出す |
| 破壊音 | シンボルが壊れたとき（ノイズバースト） |
| 倍率音 | 合計に倍率が乗ったとき |
| 支払い成功 / 失敗 / 完済 | 期の区切り |
| タップ / 購入 / 廃棄 | UI操作 |

①②とも、**表現は音程の軸だけに絞る**。①はマスの並び順、②はスピン内で
通したコンボの順番で、進むほど音階（ペンタトニック）を上がっていく
── 「積み上がっている」感。

> 金額の大小で音量・音色を変える案（段階制→連続値）も試したが、
> 「コンボの音程だけで表現する」方針に一本化した。大きい金額かどうかは
> 盤面のポップアップ `+N` / `×N`（見た目）が伝えるので、音と役割を分けている。

- **ミュートトグルを常時表示**（下部ボタン）。設定は localStorage に保存し、リロードをまたぐ。
- ブラウザの自動再生制限があるため、**AudioContext は最初のタップまで生成しない**。
- 音は完全に任意。**無音で情報が欠落してはいけない**（5.8）。

## 5.5 情報設計の原則

1. **数字は常に見える。** コイン・家賃・残スピンは常時表示。モーダルで隠さない。
2. **「あと何コイン足りないか」を出す。** 家賃バーは残額を赤字で表示（`あと 58`）。
   これがラン中の緊張の源泉。
3. **効果テキストは盤面のマスを長押しで表示。** タップは選択、長押しは説明、で統一。
4. **色に意味を持たせない。** 色覚特性への配慮として、レアリティは★の数と枠線の形で示す。

## 5.8 アクセシビリティ

- タップ対象は **44×44px 以上**。
- 盤面セルに `aria-label="ノラ猫 2コイン"` を付与。
- `prefers-reduced-motion` 対応（5.4）。
- 音は完全に任意。**無音で情報が欠落しないこと**（SEは演出の補強のみ）。
- 文字サイズは `rem` ベース。端末の文字拡大設定に追従（盤面は絵柄なので影響なし）。

## 5.9 アートディレクション

- **絵柄は絵文字ベースで開始**（開発速度優先、40種を即日用意できる）。
  ただし 04.9 の通り、後から SVG へ差し替えられる抽象を挟む。
- 背景：くすんだ生成り色（畳・砂壁のイメージ）。盤面枠は木製の質感。
- フォント：日本語は端末標準（`system-ui`）。数字だけ等幅にして桁揺れを防ぐ。
- ダークモード対応（`prefers-color-scheme`）。夜に布団の中で遊ぶ想定。
