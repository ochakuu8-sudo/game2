# 02. ゲームデザイン仕様

## 2.1 盤面

- **4列 × 5行 = 20マス**（縦持ちに最適化）。
- マスは正方形。原典の 5×4 を転置した形で、盤面情報量は同じまま縦画面に収まる。
- **隣接（adjacent）の定義は8方向**（斜めを含む）。角のマスは3マス、辺は5マス、内側は8マス隣接。
  - 隣接数がマス位置で変わるため、「端に置かれると強い/弱い」シンボルを作れる。
    ただし配置はランダムなので、これは確率的な味付けに留める。

```
      col0  col1  col2  col3
row0 [  0 ][  1 ][  2 ][  3 ]
row1 [  4 ][  5 ][  6 ][  7 ]
row2 [  8 ][  9 ][ 10 ][ 11 ]
row3 [ 12 ][ 13 ][ 14 ][ 15 ]
row4 [ 16 ][ 17 ][ 18 ][ 19 ]
```

## 2.2 シンボルプール（デッキ）と配置抽選

- プレイヤーは**シンボルの束（インベントリ）**を持つ。開始時は5個。
- 毎スピン、インベントリから **重複なしで最大20個を無作為抽出**し、20マスにランダム配置する。
  - インベントリが20個未満 → 残りは**空きマス**。
  - インベントリが20個超 → 全部は出ない。**1個あたりの出現率 = 20 / N**。
- ここが本作の根幹：**シンボルを増やすほど1個あたりの出現率は下がる**。
  だから「除去」に価値が生まれ、「濃く絞ったデッキ」と「数で押すデッキ」の選択が生まれる。

| インベントリ数 N | 各シンボルの出現率 |
| --- | --- |
| 5 | 100%（空きマス15） |
| 20 | 100% |
| 30 | 66.7% |
| 50 | 40% |
| 80 | 25% |

- 抽選は**シード付き乱数**で行う（再現性・デイリーシードのため）。

## 2.3 スピンの解決順（効果パイプライン）

実装上もっとも重要な仕様。効果は**フェーズ制**で解決し、同一フェーズ内は
**盤面インデックス昇順**で決定的に処理する（＝結果が完全再現可能）。

```
Phase 0  DRAW      インベントリから抽選し、20マスに配置
Phase 1  TICK      永続カウンタの更新（成長、変身のカウントダウン）
Phase 2  BASE      各マスの value を SymbolDef.base + instance.permanentBonus で初期化
Phase 3  ADD       加算効果（隣接ボーナス、条件付き加算）
Phase 4  TRANSFORM 変身・生成（卵→ニワトリ、コピー、盤面へのspawn予約）
Phase 5  DESTROY   破壊の解決 → 破壊されたシンボルの onDestroyed（死亡時報酬）を発火
Phase 6  MULT      乗算効果（全体倍化、隣接倍化）
Phase 7  TOTAL     合計 = Σ round(value_i)。コインに加算
Phase 8  POST      インベントリ操作（spawnの確定・破壊の確定）、実績・統計の更新
```

### 設計上のルール

- **加算より乗算が必ず後**。これを固定することで「×2 が先に乗って損した」という理不尽を消す。
- **破壊は MULT の前**。破壊されたシンボルの値は合計に含まれない（＝破壊はハイリスク）。
  ただし `onDestroyed` の報酬は破壊者のマスに加算されるので、乗算は乗る。
- **同フェーズ内の相互参照は「参照した時点の値」を読む**。順序依存を認め、
  それを盤面インデックス昇順で固定することで、説明可能かつテスト可能にする。
- 効果は必ず **1つのプリミティブの組み合わせ**で表現する（`add` / `mult` / `destroy` /
  `spawn` / `addPermanent` / `transform`）。プリミティブを増やさないことがバランス崩壊を防ぐ。

### 例：ノラ猫とネズミ

```
盤面: [🐈ノラ猫][🐁ネズミ] が隣接

Phase 2 BASE     🐈=2, 🐁=1
Phase 3 ADD      （なし）
Phase 5 DESTROY  🐈が隣接する🐁を破壊予約 → 🐁除去、🐁のonDestroyed → 🐈に +5
                 さらに🐈自身の効果 +8 → 🐈=15
Phase 7 TOTAL    15コイン
Phase 8 POST     🐁をインベントリから完全に削除（永久に失う）
```

> 破壊は「一時的に消える」ではなく**インベントリから永久に失う**。
> これによりデッキ圧縮の手段にもなり、破壊系がただの火力にならない。

## 2.4 シンボル獲得（3択）

- **毎スピン終了後**、3つの候補から1つを選んでインベントリに追加する。
- 候補のレアリティ抽選確率：

| レアリティ | 基本確率 | 備考 |
| --- | --- | --- |
| コモン | 60% | |
| アンコモン | 27% | |
| レア | 11% | 第4期以降のみ出現 |
| ベリーレア | 2% | 第7期以降のみ出現 |

- **「見送る」**を常に選べる。見送ると **+5コイン**。
  デッキを薄く保つことに明確な報酬を与えることで、「毎回何か取る」の惰性を潰す。
- 期の初回スピン後の3択は**同じ軸タグに偏らせる**（ビルドの方向性を掴ませるため）。※要検証

## 2.5 家賃テーブル（12期でクリア）

- **余剰コインは持ち越し**。支払い時に家賃分だけ差し引かれる。
- 支払い期限のスピンで所持コインが家賃未満 → **ゲームオーバー**。

| 期 | この期のスピン数 | 家賃 | 累計スピン | 必要平均コイン/スピン |
| --- | --- | --- | --- | --- |
| 1 | 4 | 25 | 4 | 6.3 |
| 2 | 5 | 50 | 9 | 10.0 |
| 3 | 6 | 100 | 15 | 16.7 |
| 4 | 7 | 175 | 22 | 25.0 |
| 5 | 8 | 275 | 30 | 34.4 |
| 6 | 9 | 400 | 39 | 44.4 |
| 7 | 10 | 550 | 49 | 55.0 |
| 8 | 11 | 750 | 60 | 68.2 |
| 9 | 12 | 1,000 | 72 | 83.3 |
| 10 | 13 | 1,300 | 85 | 100.0 |
| 11 | 14 | 1,700 | 99 | 121.4 |
| 12 | 15 | 2,200 | 114 | 146.7 |

- 総スピン **114回**。1スピン約5〜7秒（演出＋選択）で **約15〜20分**。
- 要求値の伸びは **1期あたり約 ×1.25**。指数だが、スピン数も増えるので
  「1スピンの出力」の要求は緩やかに見える。これが「まだいける」感を作る。
- 実際の難易度は後述のシミュレータで調整する（設計上はこの表を初期値とする）。

### 難易度段位

| 段位 | 家賃倍率 | 追加条件 | 解放 |
| --- | --- | --- | --- |
| 気楽 | ×0.8 | 家賃保証書を最初から所持 | 最初から |
| ふつう | ×1.0 | — | 最初から |
| 修羅 | ×1.25 | 3択が2択になる | ふつうクリア |
| 修羅+ | ×1.5 | ショップの除去コストが倍 | 修羅クリア |

## 2.6 ショップ（家賃支払い後）

支払い直後に開く。**次の期に入る前に1回だけ**。

| 商品枠 | 内容 | 価格 |
| --- | --- | --- |
| アイテム枠 ×2 | 恒久パッシブ効果（03参照） | レアリティ別 30 / 60 / 120 |
| シンボル除去 | インベントリから1つ選んで永久削除 | 初回10、以降 +10（10→20→30…） |
| リロール | 商品を引き直す | 初回5、以降倍（5→10→20…） |

- 除去コストが累進するのは、**「毎期なんとなく1個消す」を防ぐ**ため。
  デッキ圧縮は投資判断であってルーチンにしない。
- アイテム所持上限は **5個**。6個目を買うときは1個捨てる（選択の重み付け）。

## 2.7 敗北と再挑戦

- 家賃不足で即終了。リザルト画面に **「最終盤面」「デッキ全内容」「期別の獲得コイン推移グラフ」**を表示。
  - 死因が可視化されないと学習できない。グラフは必須。
- 「同じシードでもう一度」ボタンを置く。**運のせいにさせず、選択の検証をさせる**。
- 中断復帰：期の区切り・スピン境界で自動セーブ。ブラウザを閉じても続きから。

## 2.8 バランス指標（チューニングの目標値）

シミュレータ（04参照）で以下を測り、テーブルを調整する。

| 指標 | 目標値 |
| --- | --- |
| ふつう のクリア率（貪欲AI） | 25〜35% |
| ふつう のクリア率（ランダムAI） | 3%未満 |
| 敗北の期の分布 | 第5〜9期に山（序盤即死・終盤消化試合を避ける） |
| ビルド軸の勝率差 | 最強軸と最弱軸で 2倍以内 |
| 1ランの平均スピン時間 | 5.5秒以下 |

「ランダムAIで勝てない」かつ「貪欲AIで3回に1回勝てる」が、
**運ゲーではなく判断ゲーである**ことの定量的な証明になる。
